# Torve automation E2E stack

This fixture validates Torve's production automation client against real Sonarr,
Radarr, Prowlarr, Bazarr, Tdarr and qBittorrent containers. It never downloads
third-party media: FFmpeg generates an 11-minute test-pattern video with a tone,
and the local Torznab/tracker service publishes only that generated file.

## Covered workflow

1. Bootstrap connects Radarr and Sonarr to qBittorrent and the local Torznab indexer.
2. Torve performs an interactive Radarr search and grabs the generated release.
3. qBittorrent downloads it from the local seeder and Radarr imports it.
4. Bazarr synchronizes the movie, applies an English profile and exposes it as wanted.
5. Torve calls Bazarr's provider search using the credential-free embedded-subtitle provider.
6. Torve scans the imported library with Tdarr, controls a worker, accepts the staged job and verifies the durable output.

## Run

From this directory:

```powershell
docker compose up -d
docker compose ps -a bootstrap
New-Item .\state\run-live-test.flag -ItemType File -Force
..\..\gradlew.bat :shared:desktopTest --tests "com.torve.data.integrations.AutomationRealStackE2eTest" --console=plain
```

The bootstrap container must exit with code `0`. API keys are generated by the
containers, read locally by the opt-in test, and never printed or committed.

| Service | Endpoint |
| --- | --- |
| Sonarr | http://127.0.0.1:18989 |
| Radarr | http://127.0.0.1:17878 |
| Prowlarr | http://127.0.0.1:19696 |
| Bazarr | http://127.0.0.1:16767 |
| Tdarr UI | http://127.0.0.1:18265 |
| Tdarr API | http://127.0.0.1:18266 |
| qBittorrent | http://127.0.0.1:18080 |
| Local Torznab/tracker | http://127.0.0.1:18081 |

Runtime configs, generated media, downloads, keys and the live-test flag are all
under the ignored `state/` directory. To remove the containers while retaining
the test data, run `docker compose down`.
